PROJECT BRIEF: POLARIS — DIGITAL TWIN FOR INDIAN ANTARCTIC RESEARCH STATIONS

- Initiative: Smart India Hackathon (SIH) 2026 · Problem Statement ID: PS 26060.
- Stations Covered: Bharati (coastal promontory, 69°24'S, 76°11'E) and Maitri (inland oasis, 70°46'S, 11°44'E), separated by ~3,100 km of Antarctic terrain.
- Primary Objective: Build a complete, closed-loop Digital Twin platform enabling remote mission managers at NCPOR (Goa, India) to monitor microgrids, thermal balance, fuel reserves, and cryospheric conditions, detect anomalies in real time, and dispatch mission-critical mitigation actions over a satellite link.

SYSTEM TOPOLOGY & PORT ALLOCATION:
1. Antarctica Edge Gateway / Mock Server -> http://localhost:8001 (FastAPI)
   - Runs local physical world ODE simulation clock (2s tick).
   - Endpoints: GET /edge/raw-telemetry, POST /edge/scenario/inject, POST /edge/controls.
2. Polaris Digital Twin Engine / HQ -> http://localhost:8000 (FastAPI)
   - Ingests from 8001 with 500ms simulated satellite latency.
   - Runs Scikit-learn Isolation Forest + SOP rules engine.
   - Streams to frontend via WebSocket: ws://localhost:8000/ws/telemetry.
   - Proxies: POST /api/station/controls, POST /api/scenario/inject.
3. Command Center UI -> http://localhost:5173 (React 18 + Vite + Tailwind v3.4 + R3F v8)

CANONICAL TELEMETRY SCHEMA (Strict JSON Contract across all tiers):
{
  "station_id": "BHARATI" | "MAITRI",
  "timestamp": "ISO8601-UTC-String",
  "source": "synthetic",
  "confidence": "modeled",
  "ambient": { "temp_c": float, "wind_speed_knots": float, "solar_flux_w_m2": float },
  "thermal": { "internal_temp_c": float, "chp_thermal_output_kw": float, "aux_heater_kw": float, "heat_loss_kw": float },
  "microgrid": { "total_load_kva": float, "essential_load_kva": float, "science_load_kva": float, "comfort_load_kva": float, "chp_capacity_kva": float },
  "fuel": { "tank_level_liters": float, "burn_rate_lph": float, "days_of_autonomy": float },
  "controls": { "science_instruments_online": bool, "summer_wing_isolated": bool, "hatch_lockdown": bool, "aux_generator_active": bool },
  "link_status": { "type": "C-band/LEO", "latency_ms": int, "health": "ONLINE" | "DEGRADED" },
  "risk": { "anomaly_score": float, "is_anomaly": bool, "severity": "NOMINAL" | "ADVISORY" | "CRITICAL", "prescribed_actions": string[] }
}

ROLES AND RESPONSIBILTIES FOR EACH DEV MEMBER
The following are the roles and responsibilities assigned for each dev member. Keep in mind the entire project's scope using these roles.

ROLE: DEV 1 — ANTARCTICA EDGE SIMULATOR & PHYSICS ENGINE (Port 8001)

YOUR RESPONSIBILITIES:
1. Build a standalone FastAPI service simulating the on-site station server at Bharati/Maitri running on port 8001.
2. Implement a background numerical simulation loop (ticking every 1-2 seconds) based on first-principles physics:
   - Heat Loss: Heat loss = U_area * (T_internal - T_ambient) * (1 + 0.05 * sqrt(wind_speed_knots)).
   - Thermal Balance: Internal temperature delta derived from (CHP thermal generation + aux heaters - Heat Loss) / Thermal_Capacitance.
   - Microgrid Load: Total load (kVA) = Essential (180 kVA) + Science (120 kVA if active) + Comfort (60 kVA, or 20 kVA if summer wing isolated).
   - Fuel Mass Balance: JET A1 burn rate (L/h) = (Total Load * 0.22) + (Aux Heater * 0.10). Days of autonomy = tank_level / (burn_rate * 24).
3. Expose REST endpoints:
   - GET /edge/raw-telemetry: Returns un-enriched, raw physical sensor readings matching the schema.
   - POST /edge/scenario/inject: Accepts payload {"scenario_type": "BLIZZARD_80KT" | "RESUPPLY_DELAY" | "POLAR_NIGHT", "duration_seconds": int}. Alters physical parameters dynamically (e.g., wind speed ramps to 80+ kts, ambient drops to -38°C, or fuel level drops to critical threshold).
   - POST /edge/controls: Receives operator control payloads from HQ (science shed, hatch lock, wing isolate, aux generator) and applies them directly to the station actuators, altering the physics loop instantly.
4. Ensure the service runs completely headless without dependencies on scikit-learn or the HQ backend.

ROLE: DEV 2 — DIGITAL TWIN ENGINE, SATELLITE INGESTION & AI CORE (Port 8000)

YOUR RESPONSIBILITIES:
1. Build the main Polaris Digital Twin backend in FastAPI running on port 8000.
2. Satellite Ingestion Pipeline:
   - Implement an asynchronous worker (using httpx) that continuously polls http://localhost:8001/edge/raw-telemetry every 2 seconds.
   - Inject simulated polar satellite dynamics: artificial network latency (400–800 ms round trip) and network metadata in `link_status`.
   - Proxy operator control commands from POST /api/station/controls down to the edge server via POST http://localhost:8001/edge/controls.
3. Machine Learning Anomaly Detection (Non-LLM):
   - Write an offline training script using Scikit-learn to train an Isolation Forest model on 5,000 baseline rows of normal polar operating states across [ambient_temp, wind_speed, total_load, chp_heat, fuel_burn]. Save as a .joblib file.
   - Load the model in memory. On every tick, compute anomaly scores and classify status (Nominal vs. Anomaly).
4. Standard Operating Procedure (SOP) Deterministic Prescription Engine:
   - Feed telemetry and anomaly flags through an Antarctic emergency rule matrix:
     * Structural Risk: Wind > 60 knots -> Severity: CRITICAL -> "ACTION: Engage exterior hatch structural airlock sequence", "ACTION: Stow external weather sensors".
     * Thermal Collapse: Internal temp < 16°C -> Severity: CRITICAL -> "ACTION: Spin up Standby Auxiliary Generator".
     * Fuel Starvation: Days of autonomy < 30 days -> Severity: CRITICAL/ADVISORY -> "ACTION: Shed non-vital scientific payloads (MARA radar, ionosonde)", "ACTION: Isolate unoccupied summer residential modules".
5. Client Communication Layer:
   - Maintain active WebSocket connections at ws://localhost:8000/ws/telemetry to push full, enriched StationTelemetry JSON objects to the frontend every tick.
   - Expose fallback GET /api/telemetry and POST /api/scenario/inject proxying to port 8001.
